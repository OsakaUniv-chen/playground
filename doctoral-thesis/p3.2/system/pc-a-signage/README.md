# サイネージ端末

Linux 1 台で、複数の Web ページを全画面で 10 秒ずつ巡回表示する。

## 仕組み

URL ごとに 1 つの Chrome ウィンドウを全画面で常駐させ、`DWELL` 秒ごとに次の
ウィンドウを最前面に出す。ウィンドウは起動時に一度立ち上げるだけで、以降は
最前面化するだけなので、切り替えは瞬時に終わる。

この方式をとる理由は 3 つ。

- 切り替えのたびに Chrome を起動し直すと、表示時間の多くが起動とページ読み込みに
  消える。N100 のような非力な端末ほど影響が大きい
- 常駐させておけばアニメーションが途切れない。動きのあるページを選んでいるので
  ここが重要になる
- 現地でネットワークが切れても、最後に読み込んだ画面がそのまま残る

背面に回ったウィンドウの描画が止まらないよう、Chrome の background throttling を
無効化している。プロファイルは URL ごとに分けてあり（分けないと Chrome が既存
プロセスを再利用してウィンドウを個別に制御できない）、キャッシュを活かすため
削除せずに使い回す。

## コンテンツ

`urls.conf` で管理する。選定方針は 2 つ。

- **画面自体が動くもの**を優先する（変化が視線を引くため）
- **出典表記だけで自由利用できる公的データ源**を基本とする
  気象庁ホームページは「公共データ利用規約（第 1.0 版）」に準拠し、出典を記載すれば
  自由に利用できる。論文や発表で画面を掲載する場合もこの形にしておく

現在の構成は気象庁の 3 ページ（天気予報／ひまわり衛星画像／地震情報）。
交通は葛飾側で対応するページが未確定のため保留。

なお気象業務法第 23 条により気象庁以外は警報を出せない。気象アラートを扱う場合は、
自前で判定するのではなく気象庁の発表をそのまま表示する形にする。

## セットアップ

```bash
sudo apt install -y wmctrl xdotool
```

## 使い方

```bash
./signage.sh --check   # 依存関係・URL 疎通・設定の確認（GUI 不要）
./signage.sh           # 起動。Ctrl-C 一回で全ウィンドウごと終了する
./signage.sh --stop    # 別ターミナルから停止する場合
```

解像度は自動検出する。現地のディスプレイを手元で再現するときだけ環境変数で指定する。

```bash
SIGNAGE_W=1920 SIGNAGE_H=1080 ./signage.sh
```

## 設定

`signage.sh` 冒頭の変数で調整する。

| 変数 | 既定値 | 内容 |
|---|---|---|
| `DWELL` | 10 | 1 ページの表示秒数 |
| `ZOOM` | 1.0 | ページの拡大率 |
| `SUPPRESS_NOTIFICATIONS` | 1 | 実行中だけ通知バナーを止める（終了時に元の設定へ戻す） |

## 制約

- X11 前提。Wayland では `wmctrl` / `xdotool` が機能しない
- ウィンドウが落ちた場合は巡回時に検出して起動し直す

## 実機で確認済みの挙動

- `--app` と `--class` を併用したときの WM_CLASS は `<URL由来>.<--classの値>`。
  同じページの別フラグメントを並べると前半が完全に一致するため、
  最後の要素で照合しないとウィンドウを区別できない
- `--disable-background-networking` と `--disable-component-update` がないと
  "Can't update Chrome" のダイアログが別ウィンドウとして出て画面に重なる
- `wmctrl -b add,fullscreen` で `_NET_WORKAREA` の制約を超えて画面全体を覆える。
  通常のウィンドウはドックとトップバーの外に出られない
- GNOME/Mutter は全画面ウィンドウについて、スタック順の最上位ではなく
  **フォーカスされているもの**を表示する。`xdotool windowraise` ではスタック順が
  変わるだけで画面は切り替わらないため、`windowactivate` を使う
- 通知バナーが画面に被るので、実行中だけ
  `org.gnome.desktop.notifications show-banners` を false にしている
- シグナルハンドラの中で `exit` しないと、制御が巡回ループに戻って
  「ウィンドウが無い」と判定され起動し直してしまい、Ctrl-C 一回では止まらない
- Chrome の全プロセスにまとめて TERM を送ると、browser が先に落ちて
  zygote や gpu-process が孤児として残る。browser だけを終了させて
  子プロセスの後始末を Chrome に任せ、残ったものは KILL で片付ける
- URL のフラグメント（`map.html#5/34.5/137/...`）を行内コメントとして
  切り落とさないよう、設定ファイルの解析は行頭の `#` のみをコメントとして扱う
