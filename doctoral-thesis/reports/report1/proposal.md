## 1. 今回まとめたこと（次回 2026-08-07）

**天気予報を VLM に説明させるデモは行わない。** ロボットにも VLM にも中身は配らせない（§2）。要るのは内容を読む能力ではなく操作可能性を読む能力であり、それは §4 で問う。気象庁のデータは**サイネージ側の中身**として使う。

## 2. 問題設定

**現象**：インタラクティブなサイネージは「見えていない」のではなく、「**触れるものだと認識されていない**」。タッチパネルかただのモニターかは外から区別がつかない。
→ display blindness（広告と決めつけられ、そもそも見られない。Müller et al. 2009）／**interaction blindness**（見られても、操作できるとは思われない）

**過程**：関与は段階を踏む（audience funnel, Michelis & Müller）。

> 通り過ぎる → 見て反応する → **軽く触れる** → 本格的に操作する → 繰り返す

**前段が極端に細く、後段は太い**——いったん軽く触れた人は、そのまま本格的な操作まで進む割合が高い。（各段の転換率は原典を確認中）

**帰結**：詰まっているのは「**見て反応する → 軽く触れる**」の一段。主指標もここに置く（§6）。

**本研究**：自作のインタラクティブなサイネージの傍らにロボットを立たせ、第三者として**使い方**を伝える（「それ、触れますよ」「下のボックス、押せますよ」）。中身は画面が出す。VLM に読ませるのも画面の**操作可能性**であって内容ではない。

**決定問題**：「**適切なタイミングで、適切な相手に、適切な一言**」——P1・P2 で扱ってきた行動決定そのものである。入力となる状態は「情報が欲しいのに、この画面が使えると気づいていない」であり、**その状態の人を見分けること**が知覚の課題になる。

## 3. 音図がどこに効きそうか

視覚で分かるのは「立ち止まった」まで。さらに画面の前では全員が画面を向くので、P1/P2 の「正対しているか」は全員に当てはまり選択に使えない。分からないのは**声を出しているか、その声が誰に向いているか**である。

**音図が与えるのは「誰が・どの方位で・いつ声を出したか」。** 内容が要る場面では、音図の方位を使った指向性収音＋音声認識が別に要る。

| | 決定 | 音図が要る理由 | 弱いところ |
|---|---|---|---|
| 1 | **連れか、たまたま隣の他人か** → 割り込んでよいか | 方位のあいだで発話が交替していれば会話が成立している。静止画では「近くにいる」までしか分からない | 無言の連れは判別できない |
| 2 | **いつ介入するか** | 黙って見ている人と声が出ている人の区別、および発話のタイミング | 実際どれだけ声が出るかが未知 |
| 3 | **雑音下で、ロボットに話しかけたのは誰か** | 音のピーク方位を顔に対応づける | **関与した後**の話 |

3 は前の枠組みの中心だったが、相手が既に関与した後の問題である。開けたいのは**関与する前**の一段なので、1・2 を主に置く。

**先に確かめること**：サイネージの前で人はどれだけ声を出すのか。薄ければ 2 は成立せず、出番は 1 に絞られる。所内の予備収録で頻度を数えるのが最初の一手。

## 4. 決定 VLM の最小デモ

**問い**：VLM は場面を見て「今、誰に声をかけるか／誰にもかけないか」を決められるか。音図を足すと人の判断に近づくか。

**前回との違い**：前回は「音のピークがどの顔にあるか」を正解にしたため、音図に答えが書いてあった。今回の正解は**人が「今この人に声をかけるべき」と判断した相手**である。声を出している人＝声をかけるべき相手ではない（連れと話す二人は、助けるべき相手かもしれないし、邪魔してはいけない相手かもしれない）。音図は答えではなく**手がかり**として入る。

**場面**：所内で仕込む 10〜20 場面——一人で迷っている／二人で相談している／通り過ぎるだけ／一人が使っていて後ろに待つ人がいる／誰もいない（「黙る」が正解になる場面）。

**条件**：画像のみ（現行製品水準「目が合ったら寄る」に相当）vs 画像＋音図（既存の textify / overlay、`p6/try-VLM-server` の mode_A / mode_B）。音図は収録が間に合わなければ合成でよい。**問うのは「音の情報が決定を変えるか」であって、音図の推定精度ではない。**

**出力**：`{誰に / 誰にもかけない}` ＋ 理由。「誰にもかけない」を必ず入れる（入れないと強制選択になり、「いつ」が問えない）。

**正解**：同じ場面を複数人に見せ「今ロボットならどうするか」を答えてもらい、判断が一致した場面だけを使う。

**見るもの**：画像のみでどこまで行けるか／音図で上がるのはどの場面か／「誰にもかけない」を適切に選べるか（過剰介入の指標）。実機・実時間は範囲外。

## 5. 行動の選択肢

決定問題である以上、**選択肢が定義されていなければ決められない**。

| 種類 | 例 | 判断 |
|---|---|---|
| **誘導** | 「触ると週間予報も見られますよ」 | ○ 主。画面へ送る |
| **操作の案内** | 「下のボックス、押せますよ」「変な画面はホームボタンで戻ります」 | ○ 触った後で詰まらせない |
| **実演** | 画面に向かって話しかけ、応答させる | ○ 手がないので、音声のアフォーダンスはこれでしか伝えられない |
| **場所の案内** | 「一覧で見たいなら、向こうの看板の方が早いです」 | ○ 画面に固執させない |
| **内容の解説・要約** | 「明日の東京は晴れ、最高 32 度」 | **× 方針として行わない**。画面の代替になり、触る理由が消える |
| **黙る** | — | ○ 過剰な介入は害になる |

画面の構成は既知なので台詞は事前に用意できる。**VLM の役割は説明の生成ではなく行動決定である。** ただし粒度は相手に依存し（通りすがりは一言、立ち止まった人は展開可）、「どれだけ喋るか」自体が §4 の決定に含まれる。

## 6. サイネージと評価の設計

作り込みは狙わない。要るのは出来のよい画面ではなく、**現実と同じ程度に「使えると分からない」画面**である。

**設計の原則**

1. **画面を自己完結させ、ロボットを報酬にしない**：「触るとロボットと話せる」にすると、測っているものが「ロボットの言うことを聞いたか」になる。触った先の中身は画面が出す
2. **画面は読むが、読み上げない**：VLM で見るのは「今どの画面で、どこが押せるか」。データで直結させると自作の一台の横でしか動かないが、見れば読めるなら**他所の既設サイネージの横でも成立する**（一般化の条件）
3. **条件 A の接触率はゼロであってはならない**：手がかりのない画面を作れば効果量はいくらでも作れるが、それはトリック。隅に小さく「タッチで詳細」程度は置き、**手がかりはあるが誰も読まない**状態にする

**2 つのアフォーダンス**：タッチは客観的なログが取れるが、触っても音は出ない。音声は気づかれなさが大きく、**誰が言ったかを解く必要が生じる**ので音図の必然性が強い。またロボットには手がないため、タッチは言うしかないが、音声は**やってみせられる**。→ **両方載せ、主指標はタッチ、音声を第二の層**とする。

**画面の中身**：平常時は今日の天気＋次のバスをループ（動画広告に見える＝blindness が自然に起きる）、触ると週間予報・雨雲レーダー・時刻表全体（**触らないと得られない層**＝ロボットの一言が嘘にならない根拠）。気象庁 JSON と時刻表は公開データで自動更新でき、人手の維持が要らない。**これは画面側の中身であって、ロボットが持つ情報ではない。**

**条件**

| | 内容 | 何が分かるか |
|---|---|---|
| A | ロボットなし | ベースライン |
| B | あり・無差別 | 置くこと自体の効果 |
| C | あり・選択的（視覚のみ） | 選ぶことの効果。現行製品水準に相当 |
| D | あり・選択的（視覚＋音図） | **音図の寄与**（＝博論の主張） |

**指標**

- 主：**見て反応する → 軽く触れる の転換率**。GT は音図の幾何からは導けず、その後その人が実際に触れたかで決まる
- 副：本格操作への到達率、滞在時間／害：発話をきっかけに離れた割合（過剰介入）
- 決定の質：声をかけた人のうち触れた割合／触れずに去った人のうち、かけ損ねた割合
- 記録：タッチログ、通行人の計数と軌跡、音声、ロボットの発話時刻と対象

**全員を拾う必要はない。** 取りこぼしても、声をかけた相手が実際に触れれば転換率は上がる。

## 7. 今後の計画

**補うべき能力＝次の瞬間の予測**：この人が声をかけてくるか／1 秒後に誰が口を開くか／誰が画面を見ようとしているか。1 秒の粒度なら VLM で足りる。入力は現状 1 枚画像だが、Qwen3 以降は動画を受けられるため、複数フレームが本当に要るかを検証する。

**手段**：プロンプト設計・in-context learning から着手する。RL でのプロンプト学習はあり得るが、動く回路と評価信号が先。ファインチューニングはデータ量が足りず、現段階では行わない。

**継続学習の信号**：声をかけた後にその人が立ち止まったか・画面に触れたか——運用中に自動で溜まる弱いラベルであり、§6 の指標がそのまま学習信号になる。

| 時期 | 成果物 |
|---|---|
| 08-07 まで | §4 のデモ結果 |
| 中間発表まで | ロボット＋自作サイネージの最小回路を所内で通す（ノイズ込みで 7 割で動くこと）。振る舞いがヒューリスティックでも「ロボットが横にいると情報の伝わり方が変わる」と言える状態にする |
| その後 | C vs D の対照を実地で行う。所内の実績をもとに商業施設などの場所を確保しにいく |

## 8. 弱いところ・確認したいこと

- **情報提供を方針として外していること**：中身を配らせると (a) 転換率が「ロボットの話を聞いたか」に汚染され、(b) 運用コストの問題が戻る。**この切り方の確認をお願いしたい**
- **音がどれだけ出るか**：薄ければ音図の出番は「連れとの相談」だけに絞られる。予備収録で頻度を数えるのが最初の一手
- **所内では現象が起きない**：同僚は装置を知っているので interaction blindness が起こらない。所内は「動き続けるか」の確認に使い、**効果の測定は初見の人が来る場所で行う**
- **傍らに立つロボット自体は新しくない**（受付・案内ロボットは実在）。新規性は選択的な行動決定と音響モダリティの寄与に置く
- **文献**：display / interaction blindness、audience funnel の原典と各段の転換率を確認中
