# P3.2 進捗と論点（2026-08-07）

## 前提

自作のインタラクティブなサイネージの傍らにロボットを立たせ、**使い方**を伝える。中身は画面が出し、ロボットは持たない。ロボットが決めるのは「**いま声をかけるか、黙るか。かけるなら誰に、どの一言か**」。

**画面が出す中身**：

| | 内容 |
|---|---|
| 平常時 | 今日の天気、次のバス（動画広告に見える＝気づかれない状態が自然に起きる） |
| 触る／話しかけると | 週間予報、雨雲レーダー、時刻表全体（**触らないと得られない層**＝ロボットの一言が嘘にならない根拠） |

**取得元**（気象庁。自動更新でき、人手の維持が要らない）：

| | URL |
|---|---|
| 予報 JSON（3 日＋週間、信頼度 A/B/C を含む） | `https://www.jma.go.jp/bosai/forecast/data/forecast/130000.json` |
| 概況文 JSON（自然文） | `https://www.jma.go.jp/bosai/forecast/data/overview_forecast/130000.json` |
| 雨雲の動き（画面にそのまま出す） | https://www.jma.go.jp/bosai/nowc/ |
| 利用規約 | https://www.jma.go.jp/jma/kishou/info/coment.html （政府標準利用規約準拠、出典表示のみ） |

末尾の `130000` は地域コード（東京都）。差し替えれば他地域も取れる。

**実際に取得できる情報の例**（東京都、2026-08-07 11:00 発表）：

> 天気「晴れ　時々　くもり　所により　夜のはじめ頃まで　雨　で　雷を伴う」／最高気温 34℃／週間予報の信頼度 C・B・B・B・C

JSON で構造化されているため、**平常時に出す層**（今日の天気）と**触らないと見えない層**（週間予報・信頼度）を分けるのはそのままできる。ただしこの JSON は気象庁サイトの表示用データであり、正式な API として公開されているものではないため、形式が予告なく変わる可能性はある。

バス時刻表は所内シャトルの公開時刻表を使う。**これは画面側の中身であって、ロボットが持つ情報ではない。**

**ロボットが出せる一言**：

| 種類 | 例 |
|---|---|
| 誘導 | 「触ると週間予報も見られますよ」 |
| 操作の案内 | 「下のボックス、押せますよ」「変な画面はホームボタンで戻ります」 |
| 実演 | 画面に話しかけ、応答させる（手がないので、音声の使い方はこれでしか伝えられない） |
| 黙る | — |

**内容の要約・解説は行わない。** 読み上げると画面に触る理由が消え、ロボットが画面の代替になる。**天気予報を VLM に説明させるデモを行わないのはこのため。** VLM に読ませるのは画面の操作可能性（今どの画面で、どこが押せるか）のみ。

**本日の論点は 4 つ。**

---

## 1. サイネージの前で、音図がなければ下せない決定は何か

手段によらない問い。まずここが立たないと 2 に進めない。

視覚で分かるのは「立ち止まった」まで。さらに画面の前では全員が画面を向くため、P1・P2 で使った「正対しているか」は全員に当てはまり、選択に使えない。

**音図が与えるのは「誰が・どの方位で・いつ声を出したか」。** これで下せるのは、**反応が起きているか、それが誰と誰のあいだで起きているか**という判断である。

| 音図が与えるもの | 決定のどこに効くか | 画像だけなら | 音図があれば |
|---|---|---|---|
| **発話の有無とタイミング** | **いつ** 声をかけるか | 「立ち止まっている」までしか分からない | 声を出している人と、黙って見ている人を分けられる |
| **方位**（誰が声を出しているか） | **誰に** 声をかけるか | 全員が画面を向いていて選べず、最も近い人になる | 声が出ている方位の人を選べる |
| **方位のあいだの交替**（誰と誰が話しているか） | **どう扱うか** | 「近くに立っている」までしか分からない | 連れなら二人まとめて一度。相談中＝迷っている合図 |

3 行目には時間幅が要る。1 枚の音図では交替が取れないため、数秒分を累積したものを使う。

なお「雑音の中でロボットに話しかけたのは誰か」（ピーク方位と顔の対応づけ）も音図でしか解けないが、**相手が既に関与した後**の問題である。開けたいのは関与する前の一段なので、上の 3 つを主に置く。

**未確認**：サイネージの前で人は実際どれだけ声を出すのか。薄ければ 2 は成立せず、音図の出番は 1 に絞られる。→ 所内で予備収録し、発生頻度を数える。

**境界**：発話の内容は音図からは分からない。内容まで要る場面では、音図の方位を使った指向性収音＋音声認識が別に要る。今回の決定は**内容なしで下せる範囲**に限る。

## 2. VLM は「いつ・誰に」を決められるか

**VLM を HRI に適用した先行研究**：

- **[Agreeing to Interact in HRI using LLMs and VLMs](https://arxiv.org/pdf/2503.15491)**（Sasabuchi et al., 2025）：ロボットが今声をかけるべきかを LLM / VLM に判断させた（GPT-4o・Phi-3 Vision、84 場面）。問題を π(a\|s,u)（s＝人の状況、u＝ロボット自身の状況＝手持ちの用件とその緊急度）と定式化している。**取るべき行動が一つに決まる場面——手を振っている人には応じる、こちらに気づいていない人にはまず注意を引く——では正しく判断できる。難しいのは、待つ理由と待てない理由が同時にある場面である**（相手は電話中なので待つべきだが、伝えたい用件は緊急なので待てない）。入力はカメラ画像とテキストのみで、音は使っていない。また **VLM 単体では「その人がこちらを向いているか」という engagement の手がかりが取れず、顔検出と頭部姿勢推定を外付けしている**
- **[HRIBench](https://arxiv.org/pdf/2506.20566)**（Shi et al., 2025）：HRI に必要な人物知覚を 5 領域（非言語手がかりの理解／言語指示の理解／人・物・ロボットの関係の理解／social navigation／人物同定）各 200 問、計 1000 問の VQA にして 11 の VLM を評価。弱いのは 3 点：
  - **細かい非言語手がかり**：ジェスチャ単体は認識できるが視線方向が読めず、**そのふるまいが誰に向けられたものかを取り違える**（ロボットの後ろにいる別人に手を振っているのを「ロボットに手を振っている」と答える）
  - **曖昧さや誤りを含む言語指示**：「外が寒いね、テーブルの上のあれ取って」で、本当に要る上着はテーブルに無い、という場面。人は事実の誤りに気づくが、モデルは字義通りテーブルの上から選ぶ
  - **実世界の空間・物理推論**：「画面の中の人の視野を基準にすると、ロボットのグリッパーはどこにあるか」（正面／左／右／後ろ／front-left…の 8 択）に答えられない。人の視点に立って左右を入れ替えられず、Gemini-2.5-pro は front-left と答えたが正解は front-right

  加えて**性能と遅延が両立しない**：正解率が 5 割に届く o3・Gemini-2.5-pro は 1 問あたり 20〜40 秒、1 秒を切る InternVL2.5-1B/2B は正解率が 1 割台。自然な対話が崩れないとされる 0.7 秒の帯には、使える精度のモデルが無い。なお**オープンソースのモデルは RTX 3090 二枚のマシンで計測されており（こちらの環境と同等）**、クローズドのモデルは API 経由のため通信と時間帯で変動する
**参考（VLM ではなく、マニピュレーションの研究）**：

- **[S2A2](https://arxiv.org/html/2607.26047)**（Hiratsuka et al., 2026）：**RGB 画像と音図を入力にモデルを学習している**。音図はマイクアレイに MUSIC をかけ 2D グリッドに投影したもので、本研究が扱うものと同じ形式。見た目が区別できない二つの物体から、音を出している方を選んで運ぶ課題で、**視覚のみのベースライン 11% に対し 78.7%**。ただし課題は**「視覚だけでは対象が一意に定まらない」ように作られており**、ベースラインは偶然の水準（二値選択が二段で 25%）とほぼ同じである。したがってこの差は音図の寄与量ではなく課題設計の帰結であり、**読み取るべきは「MUSIC の 2D グリッドから方策が空間情報を取り出せる」ことに限られる**。また音図専用のエンコーダを学習しており、事前学習済みモデルにそのまま渡す形ではない

**VLM が HRI で弱いところ**：

- **ふるまいの宛先を取り違える**：動作が何かは分かっても、それが誰に向けられたものかを間違える。multi-party の核心的な難所
- **視線が読めない**：宛先の判断は視線に依存するため、上の弱点はここから来ている。しかもサイネージの前では全員が画面を向くので、視線はそもそも選択に使えない
- **発話は画像に写らない**：黙って画面を見ている人と、困って声に出している人が、画像では同じに見える。口の開閉は当てにならず、後ろ姿や横顔では何も分からない。これはモデルの性能ではなく入力チャネルの問題であり、VLM を大きくしても解けない
- **動作が一意に決まらない場面の判断**：ただしこれは目的の曖昧さであって、観測の不足ではない。傍観者ロボットは急ぐ用件を持たず常に待てるため、先行研究が最も苦戦した「人の状況と自分の用件の衝突」は本研究では生じない
- **精度と遅延が両立しない**：実時間は前提にしない。足りない精度は環境の設計で補う

**音図を足すと**：

- **声の方位が分かる** → 誰が話しているかの手がかりになる
- **複数フレームを入れれば、方位の交替が分かる** → 連れどうしで会話しているのか、注目の相手が切り替わったのか

**では、それで決定が変わるのか。** 音図が与えるのは「**誰が話しているか**」であって「**誰に声をかけるべきか**」ではない。**声を出している人＝声をかけるべき相手とは限らない**——連れと話している二人は、助けるべき相手かもしれないし、邪魔してはいけない相手かもしれない。手がかりから決定への変換は VLM 側の仕事である。

**ただし逆は言えない**：交替があれば連れだと言えるが、**無言の連れは判別できない**。音図は「何か起きている」ことは示すが、「何も起きていない」ことの証拠にはならない。

これが実際に決定を変えるかを確かめるのが §3 の最小デモである。

## 3. 今後の計画

**まず最小デモ**：場面を見せて「今、誰に声をかけるか／誰にもかけないか」を VLM に決めさせ、音図を足すと決定が変わるかを見る。

| | |
|---|---|
| 場面 | 所内で仕込む 10〜20 場面（一人で迷う／二人で相談／通り過ぎる／後ろで待つ人がいる／誰もいない） |
| 入力 | 3 条件：画像のみ／画像＋発話の有無だけ（方位なし）／画像＋音図（既存の textify・overlay、数秒分を累積） |
| 出力 | `{誰に / 誰にもかけない}` ＋ 理由 |
| 正解 | 同じ場面を複数人に見せ、判断が一致した場面だけを使う。**音図の幾何からは作らない** |

設計上の注意は 3 つ。**入力を 3 条件にする**——「発話の有無だけ」を挟まないと、効いたのが**音**なのか**方位**なのかが分かれず、音図である必然性を示せない。**「誰にもかけない」を必ず選択肢に入れる**（入れないと強制選択になり「いつ」が問えない）。**場面は「音がなければ解けない」ようには作らない**（画像だけで解ける場面も混ぜないと、差が出ても場面設計の産物になる）。実機・実時間・音図の推定精度は範囲外。

### 場所は三段で取りにいく

人が流れているところにいきなり持ち込むことはできない。**前の段の成果物が、次の段の交渉材料になる**という順で進める。

| 段 | 場所 | 成果物 | 次に進む条件 |
|---|---|---|---|
| **I** | 所内（手元） | ロボット＋自作サイネージが**延々と動き続ける**こと。ノイズ込みで 7 割 | 止まらずに動き続けること |
| **II** | 実地だが**人が少ない**場所 | 初見の人を相手にした転換率。ここで初めて interaction blindness が測れる（所内では同僚が装置を知っているので起きない） | 実績として提示できるデータが出ること |
| **III** | 人が多い場所（グラングリーン等） | 視覚のみ vs 視覚＋音図の対照（下記 C vs D） | — |

II の場所は「**このベースラインを置かせてください**」と持ちかけて確保する。**I の成果物がそのまま交渉材料になる**ので、I は見せられる形で作る。

### 作り込みはどこまでやるか

**サイネージ側は「広告に見える」ところまで。** 実物のデジタルサイネージはデザイナーが作り込んでおり、同等品は作れないし作る必要もない。要るのは出来のよい画面ではなく、**現実と同じ程度に「使えると分からない」画面**である（§2）。

**ロボット側は立っているだけでよい。** 傍らで使い方を伝える役なら、移動も表情も要らない。

**認識精度は環境の設計で稼ぐ。** マイクは「マイクだと分かる形」で見せる、足元に立ち位置の印を付ける、指向性マイクで拾う方向を固定する——これらは手抜きではなく、7 割で動かし続けるための設計である。

**遠隔操作を許容する。** 段 I・II では対話部分を人が操作していてよい。自動化の対象は「いつ・誰に」の決定であり、発話そのものではない。

### 手段と、次に補う能力

**手段**：プロンプト設計・in-context learning から着手。RL でのプロンプト学習は、動く回路と評価信号ができてから。ファインチューニングはデータ量が足りず、現段階では行わない。

**次に補う能力＝次の瞬間の予測**：この人が声をかけてくるか／1 秒後に誰が口を開くか／誰が画面を見ようとするか。1 秒の粒度なら VLM で足りる。ただし現状の入力は 1 枚画像で過去のフレームを持てない。Qwen3 以降は動画を受けられるため、**複数フレームが本当に要るのか**を最小デモの延長で確かめる。

**継続学習の信号**：声をかけた後、その人が立ち止まったか・画面に触れたか。運用中に自動で溜まる弱いラベルであり、下記の評価指標がそのまま学習信号になる。

### タイムライン

| 時期 | 成果物 |
|---|---|
| 次回まで | 最小デモの結果 |
| 中間発表まで | **段 I**——所内で止まらずに動き続ける最小回路。振る舞いがヒューリスティックでも、「ロボットが横にいると情報の伝わり方が変わる」と言える状態 |
| その後 | **段 II** で場所を確保し転換率を取る → **段 III** で C vs D の対照 |

**実地の評価設計**（先に決めておくもの）：

- 条件：A ロボットなし／B 無差別に発話／C 選択的・視覚のみ／D 選択的・視覚＋音図
- 主指標：**見て反応する → 軽く触れる の転換率**（audience funnel で最も細い一段）
- 害の指標：発話をきっかけに離れた人の割合（過剰介入）

## 4. 天気以外に、何を画面に出すか

選ぶ基準は 3 つ。**著作権が問題にならない**（自前か公開データ）／**人手の維持が要らない**／**触らないと得られない層がある**。3 つ目がないと「触ると〜が見られますよ」が嘘になり、転換率そのものが測れない。

| 内容 | 平常時（見るだけ） | 触ると | 出所 |
|---|---|---|---|
| 天気 | 今日の天気 | 週間予報、雨雲レーダー | 気象庁 |
| 熱中症・防災 | 「今日はアラートが出ています」 | 詳細、時間帯別の危険度 | 気象庁・環境省 |
| 交通 | 次のバス | 時刻表全体 | 所内シャトルの公開時刻表 |
| **花火大会**（季節もの） | 花火の映像をループ（**生成 AI で作る**） | **クイズ**、開催日程・アクセス | 映像は生成 AI。日程・内容は自治体の公開情報 |

**花火大会＋クイズは、実験設計として天気より強い。**

- **転換の段階が細かく取れる**：見る → 1 問目に触れる → 最後まで答える、がすべてタッチログに残る。audience funnel の各段がそのまま計測できる
- **触る動機が中にある**：クイズは答えを知りたくなる。天気は「もう知っている」人には触る理由がない
- **人が声を出す**：クイズは連れと相談する（「これどっちやろ？」）。**論点 1 の最大の未確認事項＝サイネージの前で人はどれだけ声を出すのかを、仕込まずに成立させられる**。音図の出番を作るという意味で、内容の選択が知覚の課題に直結する

**注意点**：

- **映像は生成 AI で作る**：既存の花火動画（YouTube 等）は映像著作物であり、公の場での上映は権利者の許諾が要る。生成した映像なら権利者がいない。花火は顔・手・文字を含まず暗背景で動きが主なので、生成が破綻しにくい題材でもある。数秒のループで足りる
- **実在の大会として見せない**：生成映像に実名を付ければ嘘になる。映像は演出として置き、**日程・アクセス・クイズの答えなど事実の層は自治体の公開情報から取る**
- **季節限定**：夏を過ぎると成立しないが、生成なら撮影なしで題材を差し替えられる（紅葉、イルミネーションなど）。クイズの形式自体は季節に依存しない
- **情報デバイスから娯楽デバイスへ寄る**：クイズにすると「情報が欲しいのに、この画面が使えると気づいていない」という状態の定義が弱くなる。転換率は測れるが、**主張が「触らせられるか」に寄り、「情報が届くか」から離れる**。天気・交通と併置し、クイズは触るきっかけの層として置くのが安全

## 確認したいこと

- **情報提供を方針として外していること**：中身を配らせると、転換率が「ロボットの話を聞いたか」に汚染され、運用コストの問題も戻る。この切り方でよいか
- **測定場所**：所内では同僚が装置を知っているため、interaction blindness が起こらない。所内は「動き続けるか」の確認に使い、**効果の測定は初見の人が来る場所で行う**必要がある
