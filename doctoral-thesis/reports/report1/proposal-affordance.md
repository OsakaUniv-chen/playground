## 1. 問題

インタラクティブなサイネージは、**触れることに気づかれない**。これは HCI で名前のついた現象である。

- **display blindness**：広告だろうと決めつけられ、そもそも見られない（Müller et al., Pervasive 2009）
- **interaction blindness**：画面は見られても、**触れる／操作できるとは認識されない**

**audience funnel**（Michelis & Müller 2011）はこの過程を段階に分ける：通り過ぎる → 見て反応する → 軽く触れる → 本格的に操作する → 繰り返す → 後日の行動。**最も細いのは最初の一段**であり、いったん軽く触れさせれば本格操作まではほぼ通る——開けるべき箇所は一点に絞られる。

> 転換率の具体値は**未確認**。二次情報にあった「33% / 95%」は裏が取れていない。原典（IJHCI 27(6)）に当たること。abstract で確認できるのは「660 名の通行者を観測」までである。

## 2. 既存の対策と、その限界

| 対策 | どこに手を入れるか | 限界 |
|---|---|---|
| 視覚的な誘い（アニメーション、call-to-action、シルエット／鏡像表示） | **画面の中** | 画面ごとに作り込みが要る。仕様がバラバラな既設サイネージには適用できない |
| ハニーポット効果（誰かが使っていると他人も寄る。Brignull & Rogers 2003） | **偶然の他者** | 最初の一人が要る。**制御できない** |
| 個人端末へ誘導（QR 等） | 画面の外 | 端末を出させる手間が先に立つ |

**空いている場所**：画面の外側に立ち、**制御可能な第三者**として振る舞う存在。ロボットはここに入る。

- **明示的な伝達**：「それ、触れますよ」「下のボタン、押せます」「一覧なら向こうの看板の方が早いです」
- **暗黙的な伝達＝人工のハニーポット**：ロボットが画面に向かって話しかけ、使ってみせる。二台ロボットの構成（一方がサイネージ役、一方が横で喋る）[01:31:31] はそのまま実装になる

会議で決めた通り、**ロボットは情報源ではない**。中身を持たないので、画面の仕様が変わっても、別の施設に持って行っても成立する。

## 3. 本研究の立ち位置

既存製品との違いを一行で：**AdRobot 型は「ロボットがサイネージになる」、本研究は「ロボットがサイネージの使い方を伝える」**。

| | ロボット＝サイネージ型（AdRobot 等） | 本研究 |
|---|---|---|
| ロボットの役割 | 情報源そのもの（移動する広告塔） | 既設インタフェースの傍らに立つ第三者 |
| 解く問題 | 画面に**気づかせる** | 画面が**使えると分からせる** |
| 行動決定 | 地図上のエリア → 表示内容。「目が合ったら寄る」 | いつ・誰に・どう伝えるか |
| モダリティ | 視覚＋LiDAR | 視覚＋**音図** |
| コンテンツ | 自前で用意し続ける必要がある | 持たない |

**貢献はロボットを置いたことではない**。既存製品の「目が合った人に寄る」は、視覚のみの単純ヒューリスティックが到達している現行水準であり、これが比較すべきベースラインになる。主張は「**その水準の上に、音響モダリティを入れると何が扱えるようになるか**」に置く。

## 4. 解くべき決定問題

伝えること自体は難しくない。難しいのは**選ぶこと**である。

全員に言えば、ただの騒がしい客引きになる。誰にも言わなければ何も変わらない。したがって本質的な問題は「**いつ・誰に、その一言を言うか**」——これは P1・P2 で扱ってきた行動決定そのものであり、博論の主軸に素直につながる。

決定の入力となる状態は「**情報が欲しいのに、この画面が使えると気づいていない**」。この状態にある人を見分けることが知覚の課題になる。

**喋る中身はほぼ固定でよい。** 「それ、触れますよ」「下のボタン、押せます」「今週の雨の日が分かりますよ」——画面は自分で作るので構成は既知であり、台詞は事前に用意できる。P1・P2 が扱ったのも動作の選択であって発話の生成ではない。ここは素直に揃う。

したがって **VLM の役割は説明の生成ではなく、行動決定**である——「VLM ベースでするんだったら、VLM の出力をより良くしようとすると何ができたら嬉しいの? 話者が予測できたら嬉しいよね」[01:23:20]。場面の画像と音図を入力に、「今、誰に、どの一言を出すか」を決める。音図が入るのはこの入力側であり、そこが P3.1 → P3.2 のつなぎ目になる。

**画面を VLM で読む能力は、この実験には要らない。** 自分で作る画面なので中身は既知である。それが要るのは**他所の既設サイネージの横に立つとき**だけであり、位置づけは「一般化のための能力」であって主張の中心ではない。今回のデモはその見込みを測る小さな確認に留める。

## 5. 音図がここで効く理由

視覚で分かるのは「立ち止まった」までである。**立ち止まりは興味とも困惑とも取れる**——ここが弁別できない。しかも画面の前では全員が画面を向くので、P1/P2 が使った「正対しているか」は全員に当てはまり、選択の役に立たない。

**迷いの最も早い兆候は音に出る**：

| 兆候 | 音図が与えるもの | 視覚で取れない理由 |
|---|---|---|
| 同伴者との相談（「これどうやるん？」） | 方位のあいだの発話交替 → 相談中のペアの特定 | 静止画では「近くに立っている」としか分からない |
| 独り言・ため息 | 発話の有無とタイミング | 「困っている」は外見に出にくい |
| 雑音下でロボットに向けられた発話 | 音のピーク方位を顔に対応づける | 誰の声かは画像に写らない |

前の枠組みでは「ロボットに話しかけてきた人を選ぶ」に寄っていたが、それは**相手が既に関与した後**の話だった。ここでの音は**関与する前に自然に出る声**であり、介入の引き金として筋がよい。方位が要るのは、複数人の中でどのペアが相談しているのかを決めるためである。

## 6. 作るサイネージの設計

自作する以上、何を作るかで測れるものが決まる。ただし作り込みは狙わない——「デジタルサイネージを作るのはめちゃめちゃ大変。デザイナーが考えに考えて作っている」[01:27:37]。要るのは出来のよい画面ではなく、**現実と同じ程度に「使えると分からない」画面**である。

**原則：画面を自己完結させ、ロボットを報酬にしない。**

「触ると**ロボットと話せる**」という作りは避ける。それだと測っているものが「ロボットの言うことを聞いたか」になり、「画面が使えると分かったか」ではなくなる（独立変数が指標を汚す）。またロボットが情報の出口になると、中身を持たないという §3 の立ち位置が崩れ、運用コストの問題が戻ってくる。**触った先の中身は画面が出す。**

**ロボットは画面を読む。ただし読み上げない。**

一見矛盾するが両立する。矛盾に見えるのは「情報を**持つ**」と「情報を**配る**」を混ぜているからである。

- **持たない**：中身は画面にあり、更新も画面側で完結する。ロボットは何も抱えない
- **読む**：VLM で画面を見る。そうしなければ「今そこに何が出ているか」を踏まえた具体的な一言が言えない。しかもこれは**既設サイネージへ一般化するための条件**そのものである——データで直結してしまうと自分が作った一台の横でしか動かないが、見れば読めるなら他所の画面の横でも成立する
- **読み上げない**：中身を全部喋れば、画面に触る理由が消える。ロボットが画面の代わりになってしまう

**言ってよいことの線引き**：

| | 例 | |
|---|---|---|
| **誘導**（そこに何があるか） | 「触ると週間予報も見られますよ」 | ○ 主。触りに行かせる |
| **補完**（画面にあるが分からない語） | 「その"信頼度 B"は、予報が変わるかもしれないという意味です」 | ○ 触るきっかけになる |
| **要約**（中身の圧縮） | 「明日の東京は晴れ、最高 32 度」 | △ **画面を代替する**。立ち止まらない通行人には価値があるが、触らせる目的とは別物なので指標を分ける |

| 状態 | 画面 | 位置づけ |
|---|---|---|
| 平常時 | 今日の天気＋次のバス、をループ再生 | 動画広告に見える＝blindness が自然に起きる |
| 触る／話しかける | 週間予報、雨雲レーダー、時刻表全体 | **触らないと得られない層**。ロボットの一言が嘘にならない根拠 |

**条件 A（ロボットなし）の接触率はゼロであってはならない。** 手がかりを一切持たない画面を作れば効果量はいくらでも作れるが、それは仕掛けたトリックである。現実のサイネージと同じく、**手がかりはあるが誰も読まない**程度にする（隅に小さく「タッチで詳細」など）。A に低い基線が出て初めて、blindness が実在すると言える。

**触るのか、話しかけるのか**——2 つのアフォーダンスは性質が違う。

| | タッチ | 音声 |
|---|---|---|
| 気づかれなさ | 中（試す人はいる） | **大**（画面が聞いているとは誰も思わない） |
| 指標としての質 | タッチログで客観的に取れる | 発話検出が要る |
| 音図の必然性 | 弱い（触っても音は出ない） | **強い**（誰が言ったかを解く必要が生じる） |
| ロボットにできること | **言う**だけ（手がない） | **やってみせられる**（画面に話しかけ、応答させる） |

最後の行が効く。**ロボットには手がないので、タッチは口で伝えるしかない。音声なら実演できる**——「おい、タッチパネル、お前元気か」「今、天気予報見せてんだよ」[01:57:13] が、そのまま人工のハニーポットになる。

**推奨**：両方を載せ、**主指標はタッチ、音声を第二の層**とする。タッチが客観的な主指標を与え、音声が音図の必然性とロボットの実演を成立させる。伝え方（**言う** vs **やってみせる**）は、効果を比べる要因として後から足せる。

**中身の選び方**：天気だけでは弱い。**その場所の人が実際に知りたいこと**でなければ、アフォーダンスが伝わっても触る動機がない。所内ならシャトルバスの時刻や食堂の献立。会議でも「天気予報とバス停の時刻表」[01:45:09] が挙がっていた。いずれも公開データで自動更新でき、人手の維持が要らない。

天気は気象庁（JMA）の JSON を使う。東京都なら `area_code=130000` の `forecast`（3 日予報＋週間予報、「信頼度 A/B/C」を含む）と `overview_forecast`（自然文の概況）。政府標準利用規約準拠（CC BY 4.0 互換）で出典表示のみ。**これはサイネージ側の中身であって、ロボットが持つ情報ではない。**

**記録するもの**（転換率を出すのに最低限必要）：画面のタッチログ、通行人の計数と軌跡、音声、ロボットの発話時刻と対象。

## 7. 評価

funnel の転換率がそのまま指標になる。GT は音図の幾何からは導けず、**その後その人が実際に画面に触れたか**で決まる。

**条件**：

| | 内容 | 何が分かるか |
|---|---|---|
| A | ロボットなし | ベースライン |
| B | ロボットあり・無差別（一定間隔で誰にでも同じ発話） | ロボットを置くこと自体の効果 |
| C | ロボットあり・選択的（視覚のみで決定） | 選ぶことの効果。現行製品水準に相当 |
| D | ロボットあり・選択的（視覚＋音図） | **音図の寄与**（＝博論の主張） |

**指標**：

- 主：**通り過ぎる → 軽く触れる の転換率**（詰まっている一段）
- 副：本格操作への到達率、画面前の滞在時間
- 害：発話をきっかけに離れた人の割合（**過剰介入**の指標。「情報を出しすぎると疲れる」）
- 決定の質：声をかけた人のうち実際に触れた割合／触れずに去った人のうち声をかけ損ねた割合

方針との整合：**全員を拾う必要はない**。取りこぼしても、声をかけた相手が実際に触れるなら転換率は上がる。7 割で動けばよいというのはここでも成り立つ。

## 8. 弱いところ・先に確かめること

- **音がどれだけ出るか**：サイネージの前で人は実際どれだけ声を出すのか。ここが薄ければ音図の出番は「同伴者の相談」だけに絞られる。**所内の予備収録で発生頻度を数えるのが最初の一手。**
- **所内では現象が起きない可能性**：同僚は装置を既に知っているので interaction blindness が起こらない。所内は「動き続けるか」の確認に使い、**効果の測定は初見の人が来る場所で行う**必要がある。ここは場所の確保と直結する。
- **傍らに立つロボット自体は新しくない**（受付・案内ロボットは実在する）。新規性は選択的な行動決定と音響モダリティの寄与に置き、そこを外さない。
- **文献の確認**：display blindness / interaction blindness / audience funnel / honeypot effect の原典と数値を当たる。転換率 33% / 95% は二次情報のため要確認。
