## 1. 博論の流れと本研究（P3.2）の位置づけ

### 1.1 博論の主軸ストーリー（P1 → P2 → P3.1 → P3.2）

**博士論文（仮題）：《実空間インタラクションにおけるロボットの能動的行動決定システム》**——実世界の多人数インタラクションの現場で、ロボットがセンサ入力から自律的に「**いつ、誰に、どのような動作をするか**」を決定する。システムは 2 つの軸で発展させる：**モダリティ**（視覚 → 音響を追加）と**学習方式**（実演の模倣 → 自律探索 → 事前学習済み VLM の活用）。

| # | 内容 | 貢献 | 出典 |
|---|---|---|---|
| **P1** | 商業施設の接客アンドロイド。**視覚 + 専門家（遠隔操作）の実演**による IRL | 実現場で**人間の操作者に近い水準**を達成 | RA-L 2022 |
| **P2** | 同一タスクを、**視覚 + 自律探索**の RL で。現場での自己改善 | **人間操作者を上回る** | RA-L 2023 |
| **P3.1** | **音図（sound map）を、視覚と融合しうる新たなモダリティとして確立** | 対話に関連する空間的手がかりを担う | IEEE Access 2025 |
| **P3.2** | **実空間対話ロボットのための視覚・空間音響マルチモーダル制御則の学習**（＝本提案） | 音図を行動決定に統合し、視覚/言語で解けない対象選択を補う | 新規（投稿予定） |

> **博論タイトルについて**：旧案《視覚と**音響情報**を融合した…》から「音響情報」を外した。音響を明記すると**視覚のみの P1・P2 が博論に含められなくなる**ため、モダリティを特定しない「実空間インタラクション」で括る。
>
> **P3.2 タイトルについて**：あえて「強化学習 / 逆強化学習」を書かない。制御則（policy）を得る**学習方法は何でもよく**、どこまで到達できるか現時点で未確定なため、**「マルチモーダル制御則の学習」**に留める（＝どの学習手法にも開いておく）。

### 1.2 博論における P3.2 の価値

P1-2 の行動決定は**視覚のみ**（「最も近い顔」を見る）であり、多人数かつ**話者がロボットに正対していない**場面では対象を誤る。**P3.2 ＝ P3.1 で確立した音図を行動決定に統合し**、音図が視覚 / 言語では解けない対象選択を補えることを示す。これにより博論は 1 本の線につながる：**視覚のみの行動決定（P1-2）→ 音図モダリティの確立（P3.1）→ 視覚 + 音図の行動決定（P3.2）**。

### 1.3 PSSP（音源予測）は主軸としない

P3.1 系列で試みた「将来の音源を予測する（PSSP）」路線は、P5 の統制実験（13 組 / 39 名）から次のことが示された：

- **精度不足**：+1 秒先の話者予測は、二者択一でも **54.8%** にとどまる（ベースライン 50%）。
- **効果が不明瞭**：予測駆動の注視について、その印象上の価値は**検出されなかった**。

よって **P3.2 では PSSP を中心とせず**、音図を「**現在のシーン表現**」として行動決定に用いる（反応型）。P4/P5（PSSP）は「探索したが主張には足りない**設計教訓**」として主線から外す。既発表要件は **RA-L×2 + Access×1** で充足済みであり、P3.2 は博論ストーリーを 1 本につなぐための補強である。

## 2. システム設計

### 2.1 実現手段（制御則を得る 2 つのアプローチ）

**制御則**（どの状況でどの動作を選ぶか）を得る手段として 2 通りを検討する。タイトルで学習手法を特定しないのはこのためである。

- **アプローチ 2（VLM 路線、主路線）**：**事前学習済み VLM（ファインチューニングなし）**をプロンプトし、行動決定を導出する。
- **アプローチ 1（IRL/RL 路線、副次・代替案）**：P1-2 を踏襲し、音図を入力モダリティに組み込み、**事前定義した離散動作**の中で行動決定を学習する（P1-2 との連続性のため）。

### 2.2 アプローチ 2 を優先する理由

- **VLM の利点**：事前学習済み VLM は大規模な視覚-言語の常識と推論をすでに備えており、**大量データによるファインチューニングは不要**。直接プロンプトするだけで「何が見えているか、どこから聞こえるか、誰が何を言ったか」を行動決定（どの事前定義動作を選ぶか）に写像でき、実装が速く社会実装しやすい。
- **音図の価値をクリーンに評価できる**：RL は「動作の学習」と「音図の知覚」を混在させてしまうが、VLM（学習なし）では**音図が決定に与える影響のみ**を切り出して評価できる。
- **なぜ VLA をやらないか**：「音図を加える」という貢献点を示すには VLM で十分。VLA（action 出力・要ファインチューニング）は大量データ / 算力を要し、残り時間では非現実的で、VLM を通した後の**次のステップ**として位置づける。

### 2.3 システムの入出力

- **入力**：① **RGB またはグレースケール画像**（現場のシーン、必要に応じて semseg 意味分割を追加可）② **音図**（各方向の音源 / DoA）③ **言語**（発話認識。**遠隔操作者**または**ロボットの対話相手**から）。
- **出力**：ロボットの**事前定義動作**——**事前定義した発話**（固定の台詞）または**身体動作**（注視 / 向き変え / ジェスチャ）を含む。

### 2.4 【重要】音図を VLM にどう入力するか（指導教員の疑問への回答）

ご指摘の通り、**通常の VLM は音図（acoustic map）を入力として持たない**。そこで前段の信号処理（DoA 推定・発話区間検出など、既存技術）で音図を構造化し、次の 2 通りで VLM に渡す（併用可）：

- **(A) テキスト化（記号的表現）＝主方式**：音図から抽出した情報を**自然言語 / JSON** で渡す。例：「方位 +30°（右前方）に強い発話音、方位 -60° に弱い音」「話者 A（右）が直近 5 秒発話、話者 B（左）は沈黙」。これはまさにご示唆の**「座標 X,Y 方向の音が最も強い」**という形式である。VLM は言語理解が得意なので**確実に解釈でき**、「普通の VLM をそのまま使える」。音図 → テキストの変換器が前段に入るだけで、VLM 本体はいじらない。
- **(B) 画像重畳（視覚的表現）＝補助 / 検証**：音図（方位 × 強度のヒートマップ / 矢印）をシーン画像に重畳、または別画像として渡し、空間パターンを視覚として与える。**予備検証**：音図画像を大規模 VLM（32B-AWQ 級）に直接入力する probe を実施したところ、**方向（右 / 左 / 前 など）の読み取りで約 91.7%** を得た（小型 3B/7B は崩壊）。→ **大規模 VLM なら画像重畳も一定程度読める**見込み。ただし確実なのは (A)。

**方針**：**(A) を主軸**にし、**(B) を精度向上 / 頑健性の検証**として併用する。これにより「VLM が音図を解釈できるか」という懸念に、実装可能な形で答えられる。

## 3. 応用シナリオの提案

> 選定基準：**視覚のみでは満足な効果が得にくい、あるいは誤りやすい**タスクで、**音図の追加により性能が向上する**もの。

### 3.1 ロボティックサイネージ（旗艦・指導教員提案）

- **タスク**：人流のある場所（駅前コンコース、商業施設のフロア等）にロボットを設置。普段は**デジタルサイネージ**のように情報を提示 / 待機し、**ロボットに声をかけようとする人 / 声をかけてきた人にだけ**向き直って反応を変える。
- **なぜ音図が重要か**：人流・雑音の中で「**誰が自分（ロボット）に話しかけているか**」を判定するのは視覚だけでは難しい——通行人の多くは正対せず通り過ぎ、顔だけからは「話しかけ意図」が読めない。音図は「**どの方位から自分宛の発話が来たか**」を捉え、視覚（その人が正対 / 接近しているか）と融合して**反応対象と反応タイミング**を決められる。
- **音図の必然性**：§5.0 の源①（正対しない発話者）＋ 人流からの発話者弁別。判断を誤ると「**通り過ぎる人に話しかける（誤反応）**」「**話しかけてきた人を無視する（見逃し）**」という真の代価が生じる。
- **行動決定はシンプル**：反応する / しない・誰に向くか、に絞られる。**「デジタルサイネージのロボット版」**という直感的で社会実装が信じられる応用像。
- **静かな環境**：**音声認識（ASR）も併用可**（発話内容から宛先判定を補強）。
- **課題（正直に）**：サイネージ専用のデータ収集は新規。ただし音図知覚（DoA / 発話弁別）の部分は既存のマイクアレイ + カメラデータでオフライン構築・検証できる。

### 3.2 会話ファシリテータ・ロボット（Word Wolf） — 有力な副次案（データ優位）

- **タスク**：ロボットが複数プレイヤーを相手に自由対話ゲーム（例：**Word Wolf**）を進行する。発言頻度は不均一で、ロボットはファシリテータを務める——現在の話者を注視し、間で**沈黙者の発言を促し**、**発言を独占するプレイヤーを注意し**、適時にうなずく。
- **なぜ音図が重要か**：「誰が話しているか / 誰がどれだけ沈黙しているか」を正確に判断するのは視覚では難しいが、音図（時系列動態）はそれができる（プレイヤー同士は互いに向き合い、ロボットに正対しない）。
- **なぜ有力な副次案か**：**Word Wolf 実験（P5）のマイクアレイ + カメラ実データ**があり、**視覚 vs 視覚 + 音図**の ablation をオフラインでクリーンに示せる（本案独自のデータ優位）。動機も P5 データで裏付け済み——**約 190 秒のゲーム 1 試合で、対面参加者の約 15% は発話 30 秒以下、約 49% は 44 秒以下**（中央値約 44 秒、n=104）で、確かに促しを要する「沈黙プレイヤー」が存在する。

![対面参加者の発話時間分布（P5, n=104, bin=5s）](participant_speaking_hist.png)

- **⚠ P5 との差別化（必記）**：宿主は Word Wolf だが、研究課題＝「**音図の動態が、正しいファシリテーション行動決定（沈黙者の誘導、参加の均衡）を支えられるか**」であり、P5 の**予測型注視 × 印象**（無効と実証済み）でも PSSP 予測でもない。反応型・音図駆動で、目標は参加の均等化。

### 3.3 注文取りロボット（音図必然性・強）

- **タスク**：食卓の前で複数の客に一人ずつ注文を取る。ロボットは**現在注文しようとしている人を正しく向き**、注文を進める。
- **なぜ音図が重要か**：客はしばしばメニューを見つめる / 連れを見るなどで**ロボットに正対しておらず**、視覚による話者判定は失敗する。多人数では「A を見て B に尋ねる」誤りも起きやすい。音図はアクティブな話者の方位を即時に与え、「今まさに注文を口にしたこの一言」を正しい客へ対応づけられる。

### 3.4 早押しゲーム・ロボット（音図知覚デモ）

- **タスク**：ロボットが出題し、2 名以上が早押しで回答する。ロボットは**ベルの先後を判定し**、先に押した者を指名し、採点し、次問を出す。
- **なぜ音図が重要か**：ほぼ同時に押した場合「誰が先か」は**視覚のみでは誤りやすい**（フレームレート / ブレ / 遮蔽）。音図はベル音の**時間的先後と方位**の弁別がより正確で、順序判定がタスクの核心。
- **注**：行動決定自体は単純（先に鳴らした者を指名）で、価値は**音図知覚の優位性**に集中 → 最もクリーンなデモ。

### 3.5 ティッシュ配りロボット（音図必然性は弱い）

- **タスク**：定位置で通行人に広告ティッシュを渡す。誰に / いつ / 声をかけるか否かを決める。
- **なぜ音図が重要か**：候補者が**話している / 会話中か**を判断して対象とタイミングを選ぶ。**ただし全体としては視覚主導**で、音図が貢献するのは「タイミング / 受け取り率」にとどまる。

## 4. 実装（各シナリオ × 2 アプローチ）

### 4.0 2 アプローチ共通のレシピ（一度だけ記す）

- **アプローチ 2（VLM、主路線）**：入力＝画像 + 音図表現（**§2.4 の (A) テキスト化を主、(B) 画像重畳を補助**）+ 言語。**事前学習済み VLM（ファインチューニングなし）**でプロンプトし「どの事前定義動作を選ぶか」（JSON）を出力。
- **アプローチ 1（IRL/RL、代替案）**：入力＝RGB / グレースケール画像 + 音図（semseg 追加可）を**チャネルとして積層**して CNN に入力。出力＝事前定義の離散動作。学習＝IRL→RL（P1-2 を踏襲）。
- **両者とも 音図 有 / 無 の ablation を行い**、音図の価値を示す。
- **共通の実装リスク**：① **VLM のリアルタイム遅延**（ローカル小型モデル / 頻度低減 / キャッシュが必要な場合あり）② **音図の VLM 表現**（§2.4 で対処）。

### 4.1 ロボティックサイネージ

- **事前定義動作セット**（案内の実体＝具体的応答は**遠隔操作者**または固定台詞が担い、システムは以下を決定）：
  - *頭部 / 身体動作*：(1) `look_at(人物 i)`——反応対象へ向き直る
  - *言語動作*：(2) `respond`——応答開始（固定台詞「いらっしゃいませ / 何かお探しですか」、または遠隔操作インターフェースへ「i が話しかけている」を提示）
  - (3) `idle`——サイネージ表示を継続し、反応しない
- **中核の研究上の決定**：**人流の中で「自分に話しかけている人」を、いつ・誰に対して反応するか**を判定する。DoA 等のルールは設けず、VLM / RL が判定。
- **モデル入力**：画像（シーン）、音図（各方位の発話強度・DoA・「自分宛らしさ」）、言語（ASR。静かな環境で有効）。
- **アプローチ 2**：状態記述（音図テキスト + 視覚シーン）をプロンプト → VLM が `{look_at, respond, idle}` を出力。
- **アプローチ 1**：画像 + 音図チャネル → RL / IRL が離散動作を選択。
- **指標**：**反応対象の正解率**（音図 有 / 無）、**見逃し率**（話しかけられたのに無反応）、**誤反応率**（通行人に反応）。→ ablation で音図価値を示す。

### 4.2 会話ファシリテータ・ロボット（Word Wolf 版）

- **事前定義動作セット**（ゲーム本体の自由発話は**遠隔操作者**が担い、システムは以下の事前定義動作のみを決定）：
  - *頭部 / 身体動作*：(1) `look_at(プレイヤー i)`（注視）、(2) うなずき
  - *言語動作*：(3) 相槌（簡潔で固定の backchannel）
  - *遠隔操作者への提示*：(4) `invite(プレイヤー i)`——頭部を当該プレイヤーへ向ける ＋ インターフェースに「○○に発言を促すべき」を提示。(5) `moderate(プレイヤー i)`——**独占者**へ頭部を向ける（または他プレイヤーへ向け話者交替を促す）＋「○○が独占しすぎ」を提示。
  - (6) `idle`
- **中核の研究上の決定**：**あるプレイヤーが「沈黙が長すぎる」ので invite すべきか、「独占が長すぎる」ので moderate すべきかを、いつ・誰に判定するか**（DoA 等のルールは設けない）。
- **モデル入力**：画像、音図の時系列動態（現在の話者方位、各人の累積発話 / 沈黙時間、重複・割り込み）、言語（発話認識）。
- **データ活用（本案独自の優位性）**：*オフライン*で **Word Wolf 実験の実データ**から「発話動態抽出器」を構築し、**視覚のみ vs 視覚 + 音図**の対象判定を比較（クリーンな必然性の証拠）。
- **指標**：注視対象の正解率（音図 有 / 無）、**参加の均等化**（発話時間の均衡度 / ジニ係数など）、**沈黙者の誘導成功率**（invite 後に発言したか）。

### 4.3 注文取りロボット

- **事前定義動作セット**（品目の聞き取りは**遠隔操作者**が担う）：(1) 客 i を向く、(2)「準備ができたらご注文どうぞ」、(3)「こちらお決まりですか」、(4) 終了。
- **モデル入力**：画像（食卓）、音図（各座席方向のアクティブ話者の強度 / 方位）、過去の注文履歴、言語（発話認識）。
- **アプローチ 2**：状態記述をプロンプト → VLM が `{look_at, say, done}` を出力。**アプローチ 1**：状態（画像 + 音図チャネル + 各人の注文済み / 未注文）→ RL が離散動作。
- **指標**：注視対象の正解率、注文完了度（聞き漏らし / 重複質問）。

### 4.4 早押しゲーム・ロボット

- **事前定義動作セット**：(1) 出題、(2) プレイヤー i を指名（当該へ向き変え ＋ 指名）、(3) 正誤判定と採点、(4) 次問。
- **モデル入力**：画像、音図（各ベル方向の**音イベントとタイムスタンプ**）、言語（回答認識）。
- **アプローチ 2**：ベルイベント（方位 + 時系列）をプロンプト → VLM が先押し者を指名。**アプローチ 1**：画像 + 音図チャネル → RL が動作。
- **指標**：**先後判定の正解率**（音図 有 / 無）、帰属誤判定率。

### 4.5 ティッシュ配りロボット

- **事前定義動作セット**：(1) 誰かに差し出す、(2)「どうぞ」、(3) 待機、(4) 引っ込める。
- **モデル入力**：画像、音図（各方向の発話活動 ＋ 声をかけるべき対象の方位）、言語（発話認識）。
- **指標**：受け取り率、遮断率（話している人に渡してしまったか）。

## 5. 関連研究（差別化）

- **Active Speaker Detection（AVA-ActiveSpeaker / TalkNet 等）**：「誰が話しているか」と直接重なる。差別化＝これらは**顔が見えている必要がある**が、本案は**顔が使えない（正対していない）ときに音図の方位に頼る** regime を主眼とする。
- **Robot audition / 音源定位（HARK 等）**：本研究室の文脈と親和的。**§2.4 の音図 → テキスト変換の前段**にあたる。
- **Addressee detection / multiparty HRI**：誰がロボットに話しかけているか、多者間の注視管理（**§3.1 ロボティックサイネージ**の中核）。
- **VLM-as-policy**：事前学習済み VLM でロボット行動をプロンプトする。研究室の WAM/VLA 路線とは、**ファインチューニングなし ＋ 音響モダリティ**で差異化。
- **位置づけ**：「誰が話しているか」単体では新しくない（ASD は成熟）。新規性＝① **音図をモダリティとして行動決定へ入れる**、② **AV-ASD が失効する「正対しない」regime**、③ **ファインチューニングなし**（アプローチ 2）/ P1-2 の踏襲（アプローチ 1）。
